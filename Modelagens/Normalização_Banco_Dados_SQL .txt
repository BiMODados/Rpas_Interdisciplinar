Normalização do Banco de Dados SQL Postgres
A normalização tem como objetivo organizar os dados em um banco de dados para minimizar a redundância e evitar problemas de inconsistência. Seguimos as regras de normalização (1FN, 2FN, 3FN).

1. Tabela Categoria:
Problema Identificado:

Encontramos uma redundância que seria duas tabelas com informações quase iguais no banco do primeiro ano, as tabelas de CategoriaCurso e CategoriaProduto.
E chegamos a conclusão que a melhor opção para o desenvolvimento de nosso app seria colocar tudo em um tabela dividida por um atributo de tipo e com id alfanumérico para que possamos manter o controle de nossos adm's sobre as categorias.
Os valores de id serão da seguinte maneria, para curso adicionaremos CURS_id_do_curso e para prouto PROD_id_do_curso.
Ações Realizadas:

Criação de uma tabela de Categoria que englobe as duas:
CREATE TABLE Categoria 
(
  cId VARCHAR(30) PRIMARY KEY,
  cNome VARCHAR(50) NOT NULL CHECK (LENGTH(cNome) > 0),
  cTipo VARCHAR(20) CHECK (cTipo IN ('Produto', 'Curso')),
  bIsinactive BOOL DEFAULT FALSE
);

2. Tabela MidiaCurso:
Problema Identificado:

Encontramos algo que seria uma redundância olhando para o contexto do nosso app, e chegamos a conclusão que essa tabela poderia só ser um campo, pois não teria utilidade.
Essa tabela de MidiaCurso não seria util pois não vamos necessitar de mais de uma imagem para um curso o que a torna redundante e desnecessária.
